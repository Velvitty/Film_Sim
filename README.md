# Film Filter Studio — Film Science Engine v2.0

브라우저에서 사진에 필름의 색감·입상성·할레이션과 빈티지 렌즈의 광학 효과를 적용하는 사진 처리 도구입니다. sRGB 이미지를 선형 광량으로 변환한 뒤 필름 특성곡선과 노이즈 모델을 적용하고 JPEG로 저장합니다.

**필름 포맷, 그레인·할레이션 개별 조절, 렌즈 수차, 처리 해상도 설정**을 함께 제공해 사진의 색감과 질감을 세밀하게 조절할 수 있습니다.

## 온라인으로 바로 사용하기

별도 설치 없이 **[https://film.yeon.at/](https://film.yeon.at/)** 에 접속해 브라우저에서 사용할 수 있습니다. 소개와 사용 안내는 **[온라인 안내 페이지](https://film.yeon.at/manual.html)** 에서 확인하세요.

저장소의 [`CNAME`](CNAME)에 `film.yeon.at`이 지정되어 있습니다. 온라인 앱과 내려받은 `index.html`은 같은 브라우저 처리 구조를 사용합니다.

## 주요 기능

- 컬러·슬라이드·흑백 필름 프리셋 13개
- 필름별 ISO, 유제, 감마, 입상성, 할레이션 등 설정값 표시
- 필름 룩 0~100%, 그레인·할레이션 각각 0~250% 조절
- 하프프레임·35mm·중형·대형 포맷에 따른 질감 크기 조절
- 보정 없음과 7가지 빈티지 렌즈 모델, 수차 세기 0~150%
- 원본 / 최대 24MP / 최대 12MP / 최대 6MP 처리 해상도 선택
- 원본·결과 비교, 단계별 진행 로그, JPEG 다운로드

## 실행 방법

**Code → Download ZIP**으로 내려받아 압축을 풀고 `index.html`을 브라우저에서 여세요.

Git과 Python 3가 설치되어 있다면 로컬 서버로 실행할 수도 있습니다.

```sh
git clone https://github.com/Velvitty/Film_Sim.git
cd Film_Sim
python3 -m http.server 8000 --bind 127.0.0.1
```

- 프로그램: <http://localhost:8000/index.html>
- 소개 페이지: <http://localhost:8000/manual.html>

로컬 실행에는 도메인 설정이 필요하지 않습니다. 웹 배포 시에는 정적 파일을 제공하고 사용자 도메인·DNS·HTTPS 설정을 별도로 맞춰야 합니다.

## 사용 방법

1. 처음 표시되는 사용권 계약서에 동의합니다.
2. JPG·PNG·WebP 등 브라우저에서 열 수 있는 사진을 업로드합니다.
3. 필름을 선택하고 **선택한 필름의 특성** 패널을 확인합니다.
4. **필름 룩 세기**, **입상성(그레인)**, **할레이션**을 조절합니다.
5. **필름 포맷**을 선택합니다. 같은 이미지에서 포맷이 커지면 프레임 대비 입자가 더 작아지도록 계산합니다.
6. 필요하면 빈티지 렌즈와 수차 세기를 선택합니다. 기본 렌즈는 **현대 APO 렌즈 (보정 없음)**입니다.
7. 처리 해상도를 선택하고 **필터 적용하기**를 누릅니다. 기본값은 **최대 12MP**입니다.
8. 결과를 원본과 비교한 뒤 **다운로드**로 JPEG를 저장합니다. 설정 변경 후에는 다시 적용하세요.

## 상세 사양

### 컨트롤 범위와 기본값

| 컨트롤 | 범위·선택지 | 최초 실행 기본값 | 실제 적용 방식 |
| --- | --- | --- | --- |
| 필름 | 13개 프리셋 | Portra 400 | `FILM_DB`의 색·톤·질감 값 선택 |
| 필름 룩 세기 | 0~100%, 1% 단위 | 100% | 최종 sRGB 결과 전체와 원본 픽셀 혼합 |
| 입상성 | 0~250%, 1% 단위 | 100% | `grain.sigma × 비율`로 밀도 요동 조절 |
| 할레이션 | 0~250%, 1% 단위 | 100% | `halation.strength × 비율`로 반사광 조절 |
| 필름 포맷 | 5개 | 35mm | 이미지 장변을 포맷 장변(mm)에 대응 |
| 빈티지 렌즈 | 보정 없음 포함 8개 | 현대 APO | `LENS_DB`의 광학 효과 선택 |
| 수차 세기 | 0~150%, 1% 단위 | 100% | 색수차·주변부 효과·글로우·플레어·비네팅 조절 |
| 처리 해상도 | 원본 / 24 / 12 / 6MP | 최대 12MP | 큰 입력만 비율 유지 축소 |

필름 룩 0%는 **처리 크기의 원본 RGB**를 되돌려 주는 설정입니다. 해상도 축소와 JPEG 재인코딩은 여전히 수행하므로 원본 파일을 그대로 복사하는 기능은 아닙니다. 그레인·할레이션 0%는 각 효과를 끄지만 필름의 톤과 다른 효과는 유지합니다.

**현대 APO의 비네팅:** 이름에는 “보정 없음”이라고 표시되지만 `LENS_DB.none.vig.natural`은 `0.10`이며 비네팅은 별도 단계에서 적용됩니다. 이 렌즈를 선택해도 기본 수차 100%에서는 약한 자연 감광이 남습니다. 렌즈 비네팅까지 끄려면 수차 세기를 0%로 설정하세요.

설정 변경은 자동 재렌더링되지 않습니다. 필름을 바꾼 후 바로 다운로드하면 이전 처리 결과가 저장될 수 있으므로 **필터 적용하기 → 완료 → 다운로드** 순서로 사용하세요. `처음으로`는 사진·효과 설정을 초기화하지만 처리 해상도 선택, 로그, 사용권 동의 기록은 유지합니다.

### 포맷 환산

| 내부 ID | 화면 표시 크기 | 계산에 사용하는 장변 |
| --- | --- | ---: |
| `half` | 18×24 | 24mm |
| `135` | 36×24 | 36mm |
| `645` | 56×41 | 56mm |
| `6x7` | 70×56 | 70mm |
| `4x5` | 127×102 | 127mm |

`pxPerMm = max(너비, 높이) / 포맷 장변(mm)`으로 환산합니다. 예를 들어 장변 6,000px에서 35mm는 약 166.67px/mm, 4×5는 약 47.24px/mm입니다. Portra 400의 11µm 입자는 각각 약 1.83px와 0.52px이지만, 엔진의 최소 셀 크기 1px 때문에 후자는 1px로 계산됩니다. 작은 출력에서는 포맷 간 입자 차이가 제한될 수 있습니다.

### 렌즈 모델 8개

CA는 장변 3,000px·수차 100%에서의 모서리 R/B 배율 오차 기준입니다. `soft`, `swirl`, `flare`, `vig`는 모델 계수이며 실제 렌즈의 측정 해상력이나 광학 성능 등급을 뜻하지 않습니다.

| 내부 ID | 모델 | CA R/B (px) | 주변부 soft / swirl | flare | 자연 / 기계 비네팅 |
| --- | --- | --- | --- | --- | --- |
| `none` | 현대 APO | 0 / 0 | 0 / 0 | 0 | 0.10 / 0 |
| `tessar1950` | 1950s 테사형 | 1.1 / -1.6 | 0.30 / 0.05 | 0.030 | 0.28 / 0.16 |
| `gauss1960` | 1960s 대구경 더블가우스 | 1.4 / -2.0 | 0.34 / 0.10 | 0.026 | 0.30 / 0.22 |
| `swirl58` | 58mm 스월보케 | 1.6 / -2.4 | 0.46 / 0.55 | 0.030 | 0.30 / 0.26 |
| `triplet1930` | 1930s 논코팅 트리플렛 | 2.0 / -2.8 | 0.50 / 0.18 | 0.075 | 0.36 / 0.30 |
| `thorium1970` | 1970s 토륨 렌즈 | 0.9 / -1.2 | 0.22 / 0.04 | 0.034 | 0.26 / 0.12 |
| `petzval1860` | 1860s 페츠발 | 2.6 / -3.4 | 0.62 / 0.78 | 0.060 | 0.40 / 0.42 |
| `toy` | 플라스틱 토이 | 2.8 / -3.6 | 0.66 / 0.22 | 0.055 | 0.42 / 0.50 |

실제 측방 CA는 `프리셋 CA × (이미지 장변 / 3000) × 수차 비율`입니다. 주변부는 반경의 세제곱에 따라 흐린 프록시를 섞으며 혼합 가중치를 최대 0.85로 제한합니다. 스월은 `swirl × 수차 비율 × 정규화 반경² × 0.32` 라디안으로 계산합니다. 깊이맵이나 피사체 분리를 사용한 실제 아웃포커싱 계산은 없습니다.

## 처리 파이프라인 기술문서

엔진은 8단계로 `ImageData`의 RGB를 수정합니다. 입력은 Canvas에서 얻은 8비트 RGBA이며, 중간 계산에 채널별 `Float32Array`를 사용합니다.

| 단계 | 주요 처리 | 내부 표현·특징 |
| --- | --- | --- |
| 1 | sRGB 역감마와 밝은 영역 확장 | 선형 RGB, `v × (1 + 1.45 × v²)` |
| 2 | 렌즈 수차·글로우·플레어·비네팅 | 선형 광량에서 리샘플링·블러·혼합 |
| 3 | 할레이션, 유제 산란, 염료운 확산 | 밝은 영역 추출 및 채널별 확산 근사 |
| 4 | 감도 혼합, 인터이미지, 특성곡선, 색조 이동 | 중간 회색 0.18 기준 로그 스톱 |
| 5 | 휘도·색 입상성 | 로그 스톱 공간에 노이즈 추가 |
| 6 | 선형 값 복원, 포그, 흑백 색조 | `0.18 × 2^밀도 + fog`, `dmax` 상한 |
| 7 | 인접효과와 선예도 | 제곱근 공간에서 블러 차분 강조 |
| 8 | sRGB 출력과 룩 세기 혼합 | 처리 결과와 원본 RGB 혼합, 0~255 제한 |

Canvas에 결과를 되쓴 뒤 JPEG 품질 인자 `0.96`으로 인코딩합니다. 단계 1의 확장은 밝은 영역을 모델에 넣기 위한 경험적 변환입니다. 이미 클리핑된 사진의 하이라이트 세부 정보를 복구하는 것은 아닙니다.

### 특성곡선과 LUT

`curveEval()`은 `g = 노출 스톱 × gamma`에 대해 다음 곡선을 사용합니다.

```text
g >= 0: shoulder × (1 - exp(-g / shoulder))
g <  0: -toe × (1 - exp(g / toe))
```

각 채널의 게인을 `log2(gain)`으로 더하고, 백색 기준 보정량의 72%와 프리셋 `exposure`를 인화 노출로 반영합니다. 이는 앱 자체의 톤 모델이며 제조사 감광곡선을 측정해 그대로 재현한 모델이라고 해석하면 안 됩니다.

| LUT | 크기 | 범위·용도 |
| --- | ---: | --- |
| `SRGB_TO_LIN` | 256 | 8비트 sRGB 역감마 |
| `LIN_TO_SRGB` | 4,097 | 선형 0~1 → sRGB, 선형 보간 |
| `EXP2_LUT` | 4,097 | -14~8스톱 → 2의 거듭제곱, 선형 보간 |
| 채널별 특성곡선 | 각 2,049 | -16~10스톱, 범위 밖은 끝값 사용 |
| 그레인 진폭 | 257 | `peak`·`width`·`floor`로 농도 의존 진폭 구성 |
| 주변부 수차·비네팅 | 각 513 | 정규화 반경에 따른 가중치·회전·감광 |

`EXP2_LUT`는 -14스톱 이하에서 0, 8스톱 이상에서 256을 반환합니다. 최종 sRGB 변환은 선형 값 0 이하를 0, 1 이상을 255로 제한합니다. 특성곡선의 “밀도”는 구현에서 출력 스톱으로 사용하는 값입니다.

### 그레인·할레이션·블러

- 기본 입자 셀은 `c1 = max(1, sizeUm / 1000 × pxPerMm)`이며 클럼프는 `2.7 × c1`, 큰 얼룩은 `6.8 × c1`입니다.
- 세 노이즈 층의 가중치는 `clump`로 정하고 제곱합 기준으로 정규화합니다. 미세 셀이 1.05px 이하이면 해시 노이즈를 사용합니다.
- `NoiseField`는 스무스스텝 보간을 사용하고 필요한 셀 행 두 개만 보관합니다. 난수 시드가 코드에 고정되어 있어 같은 크기·입력·설정에서 매번 새로운 무작위 그레인을 뽑는 방식이 아닙니다.
- 농도 의존 진폭은 현재 RGB 스톱 평균을 선형 밝기로 바꾼 뒤 `sqrt(Y)`로 진폭 LUT를 조회합니다. 컬러 프리셋은 독립 색 노이즈 두 개와 채널별 `layer` 가중치를 추가합니다.
- 할레이션은 `0.3R + 0.59G + 0.11B`에서 임계값을 뺀 양수 부분을 제곱하고 2.2배 해 밝은 영역을 추출합니다. 블러 후 필름별 색과 세기로 선형 RGB에 더합니다.
- 할레이션 반경은 `radiusMm × pxPerMm`입니다. 예를 들어 장변 6,000px·35mm·CineStill 800T에서는 약 75px이며, 세기 100%의 모델 계수는 0.62입니다.
- 구면수차 글로우는 채널별 밝은 영역을 추출하며 1/4 크기 프록시를 사용합니다. 주변부 수차는 약 1/3, 플레어는 약 1/12 크기 프록시를 사용합니다. 각 프록시에는 최소 크기가 있습니다.
- `blurSigma()`는 수평·수직 분리 박스 블러를 기본 3회 적용해 가우시안 블러를 근사합니다. 호출부에 따라 1회 또는 2회도 사용하며, 수직 처리에는 덮어쓴 행을 보관하는 링 버퍼를 씁니다.

이 과정은 코드에 정의한 수치 모델을 이용한 **시각적 시뮬레이션**입니다. 실제 광학계·필름 현상 공정을 정밀 계산하는 과학용 도구가 아니며 실물 필름이나 렌즈의 결과를 완전히 재현하거나 손실된 원본 정보를 복원한다고 보장하지 않습니다.

`renderFilm(srcData, opts, hooks)`는 `Promise<ImageData>`를 반환하고 입력 `ImageData`를 직접 수정합니다. `opts`에는 `filmId`, `intensity`, `grainAmount`, `halationAmount`, `format`, `lensId`, `lensAmount`를 전달하며 비율은 100%를 `1`로 표현합니다. `hooks.stage(pct, msg)`, `hooks.log(msg)`, `hooks.yield()`는 진행률·로그·UI 갱신을 연결하는 내부 인터페이스입니다. 별도의 외부 패키지 API는 제공하지 않습니다.

### 실행 구조와 메모리

렌더링은 메인 스레드에서 수행하며 Web Worker·WebGL·WebGPU는 사용하지 않습니다. `manual.html`의 WebGL 가속 소개와 현재 `index.html` 구현에는 차이가 있습니다. 일부 처리 구간에서 `setTimeout(..., 0)`으로 제어권을 반환해 화면을 갱신합니다. 이것이 모든 연산을 병렬 처리하거나 UI 지연을 없애 주는 것은 아닙니다.

처리 해상도의 픽셀 수를 `N = 너비 × 높이`라고 하면 주요 픽셀 버퍼의 크기는 다음과 같습니다. MB는 1,000,000바이트 기준의 단순 계산이며 실제 최대 메모리 사용량 측정값이 아닙니다.

| 버퍼 | 계산 | 6MP | 12MP | 24MP |
| --- | --- | ---: | ---: | ---: |
| `ImageData` RGBA | `4N`바이트 | 24MB | 48MB | 96MB |
| RGB Float32 평면 3개 | `12N`바이트 | 72MB | 144MB | 288MB |
| 스크래치 Float32 평면 2개 | `8N`바이트 | 48MB | 96MB | 192MB |
| 위 6개 배열 합계 | `24N`바이트 | 144MB | 288MB | 576MB |

여기에 원본 이미지 디코딩, Canvas 내부 버퍼, 각 효과의 프록시, JPEG 및 Base64 문자열, 미리보기 이미지 메모리가 추가됩니다. 따라서 12MP 옵션도 총 사용량이 288MB에 머문다는 뜻은 아닙니다. 해상도 제한은 원본 파일을 읽은 **후** 처리 Canvas 크기에 적용되므로 아주 큰 원본은 불러오는 단계에서도 부담을 줄 수 있습니다.

축소 비율은 `sqrt(목표 MP × 1,000,000 / 원본 픽셀 수)`이며 두 변을 반올림합니다. 작은 입력은 확대하지 않고, 반올림 때문에 결과가 명목 픽셀 상한에 아주 근접하게 달라질 수 있습니다. 고정 처리 시간·최소 RAM·최대 해상도의 공식 보장값은 코드에 없습니다.

## 출력·데이터 처리·문제 해결

- 출력은 품질 인자 `0.96`의 JPEG이며, 파일명은 `<필름 이름>_<타임스탬프>.jpg`입니다.
- 해상도 제한을 선택하면 큰 사진을 선택한 픽셀 수에 가깝게 비율 유지 축소합니다. 원본 크기로 저장하려면 **원본 그대로**를 선택하세요.
- 사진은 브라우저 메모리에서 처리되며 서버 업로드 기능은 없습니다. 폰트는 Google Fonts에서 요청합니다.
- 사용권 동의 상태와 동의 시각은 `localStorage`에 저장됩니다.
- 처리 중 여러 부동소수점 버퍼를 사용하므로 메모리가 부족하면 6MP 또는 12MP로 낮추세요. 파일 용량 제한이 없다는 안내는 브라우저 자원 제한이 없다는 뜻이 아닙니다.
- RAW·HEIC 등의 지원은 브라우저에 따라 다릅니다. 읽기 오류가 나면 JPG·PNG·WebP로 변환하세요.
- 원본 EXIF를 결과에 복사하는 기능은 없으며 JPEG 출력은 투명도를 보존하지 않습니다.
